# Batch previews, collection labels and thumbnails

My library now shows Next batch preview. Changing the size or selected collections updates the ordered list immediately; polling also refreshes it as library availability changes. Previewing never starts a batch. Each entry includes its title, collection and original-post link. Collections for next batch supports one or multiple selections; All selects every eligible collection. The sidebar is Browse your library and filters the remaining posts on screen. Both controls have plain explanations. Posts from the last run identifies historical batch membership separately.

The preview and actual batch start share public/batch-preview.mjs. It preserves the existing newest-first cohort selection, excludes unavailable retries, hidden fixtures and excluded collections, and orders that cohort by the queue's created_at/id execution order. The next batch freezes membership only when Start batch is clicked. Imports or other user actions can change a preview before then. One-video concurrency and existing polite delays remain in place.

During future real processing, a 320-pixel preview is rendered from the first frame already extracted locally, with a single FFmpeg thread. The bounded JPEG (maximum 128 KiB) is stored privately under .research-data/thumbnails with a hash-based filename. The complete video, audio and analysis frames are still deleted. Local image routes validate names, file type and size and reject symlinks. Result and recipe cards use a plain No preview placeholder when an image is absent or unreadable. No external thumbnail service or network acquisition is used. Media-retention wording now distinguishes the retained small preview from temporary analysis frames.

Existing processed records were inspected for retained local video files: none were found in .research-data, so no historical thumbnails were made and no media was downloaded. This inspection did not read browser login data. Thumbnail metadata is added to dashboard responses from existing image files without rewriting old database results.

Validation: 137 Windows automated tests passed, including shared cohort/order/exclusion tests, frozen-selection contract with a stand-in queue and zero requests, bounded image/name validation, safe local serving and placeholder fallbacks. A real installed-FFmpeg smoke test used only a synthetic local image and verified a 320x240 JPEG; it started no batch, used no Instagram video and made no paid calls. Live acceptance verified changing 3 to 5 updates the preview, multiple collection selection works, and the three displayed IDs exactly match the server selection. Existing results show placeholders. Production thumbnail generation during a future real batch remains untested; none was authorized here.
